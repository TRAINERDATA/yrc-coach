# 수영 데이터 단축어 (아이폰 + 애플워치)

러닝 단축어와 같은 방식이고, 찾는 유형만 다릅니다. 동작 6개.

전송 주소: `https://yrc-coach.onrender.com/ingest/<수영 토큰>` (브리핑 페이지: `/brief/<수영 토큰>`)

| # | 동작 | 설정 |
|---|---|---|
| 1 | 건강 샘플 찾기 | 유형 **수영 거리** · 시작일 과거 56일 · 단위 **m** · 그룹화 **시간** · 필터 추가 **소스 이름 다음을 포함 "Watch"** · 파일이 유실됨 끄기 · 제한 끄기 |
| 2 | 건강 샘플 찾기 | 유형 **수영 스트로크 수** · 과거 56일 · 그룹화 **시간** · 파일이 유실됨 끄기 |
| 3 | 건강 샘플 찾기 | 유형 **심박수** · 과거 **14일** · 그룹화 **없음** |
| 4 | 건강 샘플 찾기 | 유형 **활동 에너지** · 과거 56일 · 단위 **kcal** · 그룹화 **시간** · 소스 이름 포함 "Watch" · 파일이 유실됨 끄기 |
| 5 | 텍스트 | 아래 8줄 제목 + 각 줄 아래 변수 토큰 (dates = 토큰 → 시작일 → 날짜 포맷 ISO 8601, values = 건강 샘플 그대로) |
| 6 | URL 콘텐츠 가져오기 | 수영 전송 주소 · POST · 본문 요청 파일 = 텍스트 |

```
##swim_dates
(1번 시작일)
##swim_values
(1번 건강 샘플)
##strokes_dates
(2번 시작일)
##strokes_values
(2번 건강 샘플)
##hr_dates
(3번 시작일)
##hr_values
(3번 건강 샘플)
##energy_dates
(4번 시작일)
##energy_values
(4번 건강 샘플)
```

주의: 찾기 동작이 앞 동작 아래 붙으면 "필터링"으로 바뀜 → 파란 건강 샘플 토큰 → 변수 지우기. 자동화: 시간대 매일 (저녁 수영이 끝난 뒤, 예: 22:30 또는 아침 브리핑 전 08:10) 즉시 실행.

서버가 계산하는 것
- 수영 세션 = 수영 거리가 100m 이상인 시간대. 시간은 심박 샘플 수 × 4.5초, 스트로크·칼로리는 그 시간대 합계
- 100m 페이스, 25m당 스트로크(효율), SWOLF 근사, 세션 칼로리
- 식단: Mifflin-St Jeor 기초대사량 × 활동계수 + 운동 소모 − 500kcal (최소 1,400). 단백질 1.6g/kg
